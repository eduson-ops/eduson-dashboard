
# Eduson Booking Design Book 2026

Версия: 2026.11.06  
Контур: booking/index.html, booking/styles.css, booking/app.js  
Назначение: единая визуальная и поведенческая система для операционного букинга Eduson.

## 1. Манифест анти-нейрослопа

Eduson Booking — рабочий инструмент для принятия решений в течение минуты. Каждый экран показывает операционный контекст, следующий шаг и источник правды.

### Принципы

1. Сигнал важнее декора. Цвет, размер и движение сообщают состояние записи.
2. Один экран — одна задача. Control Tower распределяет нагрузку, Queue закрывает подтверждения, Wizard создаёт запись.
3. Данные ближе к действию. Кнопка находится рядом с записью, которую она меняет.
4. Состояние всегда видно. Используем явные статусы, даты, московское время и свежесть данных.
5. Сначала структура. Сетка, отступы и типографика создают иерархию до добавления цвета.
6. Никакого декоративного шума. Нет случайных градиентов, emoji-навигации, псевдо-3D и коричневых акцентов.
7. Сохранение контракта. Поведение, DOM-id, data-action и имена функций сохраняются для frontend.test.mjs.
8. Доступность по умолчанию. Фокус виден, интерактивные элементы доступны с клавиатуры, reduced motion отключает декоративные переходы.
9. Ошибки объясняют следующий шаг. Текст ошибки содержит действие: повторить, открыть запись, проверить очередь.
10. Изменение обратимо. Черновики визарда, расписания и отчётов сохраняются локально до отправки.

### Запреты

- #c99d65, #806d57 и близкие грязно-коричневые оттенки.
- Chevron-степпер через clip-path.
- Скрытые статусы, авто-переходы без подтверждения и действия без результата.
- Поля без подписи, кнопки только с иконкой без aria-label.
- Текст «готово» без подтверждения от API.
- Разные названия одного состояния в разных экранах.

### 2.2 Типографика

- Основной интерфейс: Inter, fallback system-ui, sans-serif.
- Редкие дисплейные заголовки: Geist, fallback Inter.
- Числа, время, идентификаторы: JetBrains Mono.
- Все таймеры, цены, KPI и табличные числа используют font-variant-numeric: tabular-nums.
- Заголовки используют плотность 600–700 и отрицательный трекинг до -0.02em.
- Основной текст: 14–15 px, межстрочный интервал 1.45.
- Вторичный текст: 12–13 px, межстрочный интервал 1.5.
- Подпись поля: 11–12 px, верхний регистр только для коротких eyebrow-меток.

### 2.4 Double-Bezel

Базовая поверхность использует внутренний верхний блик и мягкую внешнюю тень:

    .surface {
      border: 1px solid var(--border);
      box-shadow:
        inset 0 1px 0 rgba(255,255,255,.08),
        0 14px 38px rgba(0,0,0,.24);
    }

На hover добавляется только один внешний слой:

    .surface:hover {
      border-color: rgba(124,109,255,.34);
      box-shadow:
        inset 0 1px 0 rgba(255,255,255,.1),
        0 18px 44px rgba(0,0,0,.32),
        0 0 0 1px rgba(99,91,255,.08);
    }

Не смешивать Double-Bezel с тяжёлой тенью, градиентом и backdrop-filter без измеримой причины.

## 3. Физика интерфейса и анимации

### 3.1 Базовая кривая

Все переходы используют cubic-bezier(0.16, 1, 0.3, 1).

- Hover: 140–180 ms.
- Открытие drawer и dialog: 240–320 ms.
- Переключение вкладки: 180 ms.
- Toast: вход 220 ms, выход 160 ms.
- prefers-reduced-motion: reduce отключает transform и animation.

### 3.2 Нажатие

Интерактивная поверхность на нажатии делает scale(0.98) на 100–140 ms. Текст и layout не прыгают.

### 3.3 Radar pulse для текущего часа

Текущий час помечается .is-current-hour.

    .is-current-hour {
      position: relative;
      border-color: rgba(52,211,153,.5);
    }
    .is-current-hour::before {
      content: "";
      width: 7px;
      height: 7px;
      border-radius: 50%;
      background: var(--emerald);
      box-shadow: 0 0 0 0 rgba(52,211,153,.55);
      animation: radar-pulse 1.8s ease-out infinite;
    }
    @keyframes radar-pulse {
      0% { box-shadow: 0 0 0 0 rgba(52,211,153,.55); }
      70% { box-shadow: 0 0 0 9px rgba(52,211,153,0); }
      100% { box-shadow: 0 0 0 0 rgba(52,211,153,0); }
    }

Дот находится рядом со временем, поэтому пользователь видит связь между маркером и слотом.

### 3.4 Skeleton screens

Skeleton применяется только при первом запросе, когда структура уже известна:

- сохраняется высота карточки;
- shimmer не занимает больше 1.5 секунд;
- после загрузки skeleton заменяется контентом без layout shift;
- при повторном обновлении показывается тонкая строка role=status, а не полный skeleton.

## 4. Спецификация компонентов

### 4.1 Bento KPI

Сетка KPI имеет 4 колонки на desktop, 2 на tablet и 1 на mobile. Каждая карточка содержит label, число, delta и короткий контекст.

- Сильное число: 28–36 px, tabular-nums.
- Delta использует emerald/amber/carmin по смыслу.
- Клик открывает соответствующий drawer или filtered view.
- Не использовать декоративные sparkline без данных.

### 4.2 Ribbon Hour Scroller

Ribbon — горизонтальная лента часов Control Tower.

- Фиксированный шаг 72–88 px.
- В каждом часе: время, свободные МИМК, места и короткий статус.
- Текущий час получает .is-current-hour.
- Лента скроллится клавишами и touch.
- Нажатие открывает Action Drawer с тем же data-time.
- На mobile лента не ломает страницу и не скрывает scrollbar-индикатор.

### 4.3 Linear Stepper

Степпер визарда состоит из точек, линий и коротких подписей.

    [1 Данные] ───── [2 Время] ───── [3 Подтверждение]

Состояния:

- is-complete: emerald dot и заполненная линия.
- is-active: indigo dot и glow.
- is-upcoming: muted dot и тонкая линия.
- is-blocked: carmin dot только для ошибки.

Не использовать chevron, clip-path, стрелки в виде псевдо-стикеров или текст без визуального порядка.

### 4.4 Age Chips

Возрастные группы — интерактивный bar:

    7–8 · 9–10 · 11–12 · 13–14 · 15+

- Один выбранный возраст имеет indigo fill.
- Нажатие обновляет hidden age и запрашивает доступные слоты.
- 15+ передаёт числовое значение не меньше 15.
- Chips доступны с клавиатуры и имеют aria-pressed.
- В расписании возрастные теги показываются отдельно от выбора возраста ученика.

### 4.5 Status Badges

Статус состоит из точки, текста и, при необходимости, дедлайна.

| Состояние | Цвет | Текст |
| --- | --- | --- |
| confirmed | emerald | Подтверждено |
| in_progress | emerald | В эфире |
| pending | amber | Ожидает подтверждения |
| overdue | carmin | Просрочено |
| cancelled | carmin | Отменено |
| available | indigo | Свободно |

Текст статуса всегда совпадает с серверным state и не подменяется декоративным синонимом.

### 4.6 Cancel Cards

Карточка отменённой записи содержит:

- ученик;
- дата и время;
- причина;
- источник отмены;
- статус;
- кнопку Перезапись.

Перезапись открывает визард с предзаполненными именем, возрастом, контактами и комментарием причины. Сохранение создаёт новую запись, а журнал отмены остаётся неизменным.

### 4.7 Action Drawers

Drawer открывается из часа, KPI или списка.

- Заголовок: дата, время, фильтр и свежесть данных.
- Первый блок: доступные МИМК и capacity.
- Второй блок: записи часа и статусы.
- Третий блок: действия (Назначить, Перезапись, Экспорт).
- Закрытие: Escape, крестик, клик по backdrop.
- После мутации drawer обновляет только затронутую запись и сохраняет фокус.

## 5. Экранные спецификации

### 5.1 Control Tower

Цель: администратор видит нагрузку дня и сразу находит дефицит.

Состав:

1. Topbar: дата, московские часы, live-индикатор.
2. Bento KPI: всего записей, подтверждено, в работе, без отчёта.
3. Ribbon Hour Scroller: часы 09:00–22:00.
4. Capacity matrix: МИМК, места, возрастные группы.
5. Facepile дежурных МИМК.
6. Последние алерты и кнопка перехода к очереди.

Действия:

- нажать KPI → открыть фильтр;
- нажать час → открыть Drawer;
- нажать дефицит → открыть список свободных МИМК;
- нажать refresh → обновить bootstrap и freshness.

### 5.2 Drawer

Цель: решить конкретный час без перехода со страницы.

Drawer показывает:

- выбранный час;
- количество мест и резерв;
- список МИМК с возрастными чипами;
- записи учеников;
- быстрые действия назначения и отмены.

Инвариант: data-time и state.drawerHour всегда совпадают.

### 5.3 Очередь подтверждения

Цель: закрывать подтверждения до дедлайна.

Каждая строка содержит ученика, слот, дедлайн, контакт и статус. Просроченная строка получает carmin, близкий дедлайн — amber. Кнопка подтверждения меняет статус и обновляет очередь без перезагрузки.

Порядок сортировки: сначала ближайший confirmationDueAt, затем дата и время слота.

### 5.4 Визард записи

Цель: создать запись за три коротких шага.

1. Данные: имя, контакты, возрастные chips, комментарий.
2. Время: выбранная дата, Ribbon часов, свободные места.
3. Подтверждение: сводка, источник сделки, кнопка создания.

Состояния: загрузка слотов, пустой результат, ошибка, сохранённый черновик, успешная запись. При отмене шага данные не теряются. Вызов API создаёт запись только после проверки выбранного времени.

### 5.5 Мой день МИМК

Цель: провести текущие и ближайшие занятия.

Верхний блок показывает «Следующий урок», ниже — список дня. Для каждого урока доступны:

- начать;
- завершить;
- открыть отчёт;
- открыть историю изменений.

Цвет emerald означает активный урок. После завершения появляется CTA отчёта и точный пакет продажи.

### 5.6 Расписание и слоты

Цель: администратор редактирует открытые часы на 14 дней.

Экран содержит:

- выбор МИМК;
- age tags;
- переключатель недель;
- сетку 24 часов × 14 дней;
- копирование недели;
- очистку дня;
- лимит резерва;
- сохранение и сброс черновика.

Черновик хранится отдельно от опубликованного расписания. Конфликт версии показывает предупреждение и предлагает загрузить актуальные данные.

### 5.7 Журнал отмен

Цель: видеть причины отмен и быстро восстановить продажу.

Фильтры: дата, источник, причина, возраст. Карточка содержит причину и кнопку Перезапись. Нажатие заполняет визард, но не удаляет исходную отмену.

Цвета: carmin для отмены, indigo для действия, muted для архивных полей.

### 5.8 Отчёты и аналитика

Цель: зафиксировать факт урока и коммерческий результат.

Отчёт содержит:

- практика / направление;
- точный пакет продаж;
- способ оплаты;
- договорённость;
- возражение;
- канал;
- сумма нетто;
- ссылка на запись.

Пакеты:

- 1 месяц;
- 3 месяца;
- 6 месяцев;
- 12 месяцев;
- 1+1 (124к).

Карточка отчёта показывает прогресс «Запись создана → Урок подтверждён → Урок проведён → Отчёт заполнен». Оплата запускается отдельным действием после сохранения отчёта.

## 6. Адаптивность

- Desktop ≥ 1280 px: sidebar, 4 KPI, полноценный drawer.
- Tablet 761–1279 px: sidebar 150 px, 2 KPI, drawer 420 px.
- Mobile ≤ 760 px: горизонтальная навигация, 1 KPI, таблицы внутри scroll-контейнера, drawer на всю ширину.
- Touch targets не меньше 40 × 40 px.
- Фиксированный sidebar не используется на mobile.
- Никогда не скрывать основное действие только из-за ширины экрана.

## 7. Контракт с кодом

Сохраняются функции renderNewOverview и renderNewMobileExact, даже если вкладки «Обзор» и «Mobile first» скрыты из сайдбар-меню. Их наличие требуется тестами и будущими режимами.

Сохраняются:

- data-action, data-id, data-view, data-time;
- DOM-id визарда и фильтров;
- роли admin, call_center, confirmation, sales;
- API-эндпоинты /bootstrap, /bookings, /schedule, /reports, /payments;
- кэш-бамп v=ui-mode-20261106-36.

## 8. Проверка качества

Перед выпуском проверяются:

1. node --test booking/*.test.mjs
2. node --test tests/*.mjs
3. отсутствие #c99d65 и #806d57;
4. наличие renderNewOverview и renderNewMobileExact;
5. наличие .is-current-hour, Linear Stepper и Age Chips;
6. работа drawer, отмены и Перезапись;
7. точный пакет 1+1 (124к);
8. кэш-бамп во всех ссылках на booking/styles.css и booking/app.js;
9. desktop, tablet и mobile smoke-check.

Критерий готовности: все 66 тестов проходят, экранные контракты сохранены, а визуальная проверка подтверждает отсутствие слопа и коричневых артефактов.
