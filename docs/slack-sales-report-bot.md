# Slack-бот отчёта для сейлов

## Найденная существующая реализация

В ветке `C:\Users\being\Documents\Codex\2026-09-10\x20\outputs\evening-report` уже есть проверенный вечерний отчёт для Slack. Он собирает данные из Google Sheets и отправляет отчёт в канал `#вечерний-отчет` в 22:30 по Москве. Реализация поддерживает разбивку длинного сообщения, повторные попытки, неопределённую доставку, теги менеджеров и защиту от повторной отправки.

Эта реализация остаётся источником формата и расчётов. Для Booking её нужно перевести на PostgreSQL/API, чтобы отчёт использовал тот же источник, что и рабочий букинг.

## Отчёт сейла

Каждый сейл получает личное сообщение после обновления итоговой карточки дня. В сообщении видны:

- проведённые уроки;
- отмены и причины;
- оплаты и суммы;
- текущий статус отчёта;
- ссылка на Booking;
- ссылка на сделку AmoCRM;
- ссылка на запись урока;
- незаполненный отчёт после завершённого урока.

Почасовая сводка отправляется владельцу Booking в личные сообщения, а не в общий чат. В ней видны методисты, количество записей, подтверждённые уроки, резервы, отмены, начатые и завершённые уроки.

## Источники Booking

```text
PostgreSQL bookings
  ├─ booking events: created, confirmed, cancelled, started, completed
  ├─ reports: отчёт ИМК
  ├─ payments: отчёт об оплате
  └─ users/schedules: сейлы и открытые часы
```

Google Sheets остаётся резервной копией. Бот не пересчитывает бизнес-факты из Slack и не создаёт новые уроки или оплаты.

## События личных уведомлений

| Событие | Получатель | Сообщение |
|---|---|---|
| назначение на основной слот | назначенный сейл | новый урок и кнопка Booking |
| назначение в резерв | назначенный сейл | резервный урок с предупреждением |
| переназначение | старый и новый сейл | кто передал и кому назначено |
| старт урока | сейл | урок начат |
| завершение урока | сейл | требуется отчёт ИМК |
| 15 минут после окончания | сейл | напоминание о незаполненном отчёте |
| сохранение отчёта | сейл | отчёт принят |
| отмена | сейл | причина отмены |

Тестовые и архивные записи не отправляются сотрудникам.

## Требования к Slack

Конфигурация хранится вне webroot:

```json
{
  "enabled": true,
  "token": "xoxb-...",
  "teamId": "T...",
  "summaryChannelId": "C...",
  "summaryUserId": "U0BQ6CTN3D2",
  "baseUrl": "https://booking.82.148.17.109.sslip.io/",
  "staffMap": {
    "booking-user-id": "slack-user-id"
  }
}
```

Бот проверяет принадлежность пользователей к команде, исключает удалённых пользователей и ботов, сохраняет очередь доставки в PostgreSQL и не повторяет неопределённую отправку автоматически.

## Приёмка

1. Новый основной урок создаёт одно личное Slack-сообщение.
2. Резервный урок получает явную пометку `Резерв`.
3. Переназначение уведомляет текущего и нового сейла.
4. После завершения урока появляется запрос отчёта.
5. После заполнения отчёта напоминание исчезает.
6. Отмена отправляет причину.
7. Ежедневная сводка совпадает с админской статистикой Booking.
8. Повторная обработка не создаёт дублей.
