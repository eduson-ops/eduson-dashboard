# Eduson Booking UI Playbook 2026

Версия: 2026-11-06  
Область: \`booking/index.html\`, \`booking/styles.css\`, \`booking/app.js\`, \`booking/core.mjs\`, \`booking/*.test.mjs\`, \`tests/*.mjs\`.

## 1. Назначение и рабочий принцип

Плейбук задаёт единый инженерный способ развивать букинг Eduson в стиле Obsidian 2026 / Linear Dark Glow. Каждый экран должен сокращать время оператора до следующего действия, показывать состояние данных и оставаться проверяемым через существующие тестовые контракты.

Работа проходит в порядке:

~~~text
контракт → состояние → компонент → действие → обратная связь → тест → визуальная проверка
~~~

\`booking/app.js\` отвечает за состояние, маршрутизацию и действия.  
\`booking/styles.css\` отвечает за визуальные токены, геометрию, адаптивность и анимации.  
\`booking/index.html\` подключает версии ресурсов и корневой контейнер.  
\`booking/core.mjs\` содержит чистые функции, которые можно проверять без браузера.  
Тесты проверяют публичное поведение, а не внутреннюю структуру DOM.

## 2. Правила компонентов

### 2.1. Токены

Используйте только семантические токены:

| Токен | Значение | Применение |
| --- | --- | --- |
| \`--canvas\` | \`#08090a\` | фон приложения |
| \`--surface-1\` | \`#0e1012\` | основная поверхность |
| \`--surface-2\` | \`#14171a\` | вложенная поверхность |
| \`--line\` | \`rgba(255,255,255,.08)\` | границы и разделители |
| \`--text\` | \`#f3f4f6\` | основной текст |
| \`--muted\` | \`#8b93a7\` | вторичный текст |
| \`--indigo\` | \`#635bff\` | фокус, день, основной CTA |
| \`--indigo-soft\` | \`#818cf8\` | hover и мягкий фокус |
| \`--emerald\` | \`#34d399\` | подтверждено, активно, в эфире |
| \`--amber\` | \`#fbbf24\` | ожидание, дедлайн, утро |
| \`--rose\` | \`#f87171\` | дефицит, отмена, просрочка |
| \`--bezel\` | \`inset 0 1px 0 rgba(255,255,255,.08)\` | Double-Bezel |
| \`--ease-out\` | \`cubic-bezier(.16,1,.3,1)\` | переходы |

Цвета \`#c99d65\` и \`#806d57\` запрещены. Не вводите новые коричневые оттенки.

### 2.2. Double-Bezel

Карточка получает внешний бордер и внутренний верхний свет:

~~~css
.new-panel,
.new-metric-card,
.new-hero,
.new-drawer-row {
  border: 1px solid var(--line);
  box-shadow: var(--bezel);
  background: var(--surface-1);
}
~~~

Внешняя тень должна усиливаться только для слоя поверх интерфейса: drawer, dialog, toast. Не используйте тяжёлые тени на каждом блоке.

### 2.3. Bento KPI

Bento KPI показывает одну метрику, единицу измерения и короткое объяснение. Карточка не содержит вторичный график без действия.

Обязательная структура:

~~~html
<article class="new-metric-card bento-kpi success">
  <div><span>Подтверждено</span><strong>24</strong></div>
  <small>за выбранный день</small>
</article>
~~~

\`success\`, \`warning\`, \`danger\` и \`indigo\` передают семантику состояния. Числа используют \`font-variant-numeric: tabular-nums\`.

### 2.4. Ribbon Hour Scroller

Ribbon показывает часы выбранного дня в drawer. Каждая кнопка:

- имеет \`data-action="hour"\`;
- содержит \`data-time="HH:00"\`;
- показывает счётчик записей, если он больше нуля;
- получает \`active\` для текущего часа;
- сохраняет клавиатурный фокус.

Скроллер не должен скрывать активный час после обновления данных.

### 2.5. Linear Stepper

Степпер визарда использует линейный индикатор прогресса. Старый chevron \`clip-path\` запрещён.

Каждый шаг содержит:

- номер;
- короткое имя;
- состояние \`active\`, \`complete\` или \`upcoming\`;
- связь с \`data-action="wizard-step"\` и \`data-step\`.

Переход к шагу 3 разрешён только после выбора доступного слота. При недоступном слоте приложение возвращает пользователя к шагу 2 и показывает причину.

### 2.6. Age Chips

Возрастные чипы применяются в фильтрах расписания, назначении МИМК и отчётных срезах. Базовый набор:

~~~text
7–9 · 10–12 · 13–15 · 15+
~~~

Чипы должны быть кнопками, а не декоративными \`span\`. Активный чип имеет \`aria-pressed="true"\` и цвет индиго. Неактивный чип не меняет размер при переключении.

Возрастная фильтрация должна быть включительной на границах. Проверка \`8–9\` включает 8 и 9, но исключает 7 и 10.

### 2.7. Status Badges

Используйте короткий текст и цвет:

- \`Подтверждено\` — emerald;
- \`Ожидает\` — amber;
- \`Дефицит\`, \`Отмена\`, \`Просрочено\` — rose;
- \`Резерв\` — amber с дополнительной подписью;
- \`В работе\` — indigo.

Цвет не является единственным носителем смысла. Статус всегда дублируется словом.

### 2.8. Cancel Cards

Карточка отмены показывает:

1. имя ученика и возраст;
2. дату и время;
3. причину;
4. кто отменил;
5. текущее состояние места;
6. кнопку \`Перезаписать\`.

\`Перезаписать\` открывает визард с предзаполненными именем, возрастом, родителем, телефоном, CRM-ссылкой, признаками компьютера и присутствия родителя. В комментарий добавляется источник: \`Перезапись из отменённого урока\`.

### 2.9. Action Drawers

Drawer открывается из часа, не теряя выбранную дату. Он содержит:

- ribbon часов;
- KPI часа;
- список учеников;
- статус подтверждения;
- назначенного МИМК;
- действия \`Экспорт CSV\`, \`Переназначить\`, \`Оставить резерв\`.

Действия должны вызывать реальные обработчики. Запрещены \`location.reload()\` и пустые refresh-заглушки.

## 3. Do''s and Don''ts

### Делайте

- Используйте один термин для одного понятия: \`подтверждение\`, \`отмена\`, \`резерв\`, \`назначение\`.
- Давайте кнопке глагольное имя: \`Подтвердить\`, \`Переназначить\`, \`Заполнить отчёт\`.
- Оставляйте текущую дату и час видимыми после любого действия.
- Показывайте причину ошибки рядом с полем или действием.
- Отключайте кнопку на время мутации и повторно включайте её в \`finally\`.
- Сохраняйте черновики форм через \`makeDraftStore\`.
- Передавайте \`version\` в мутациях для защиты от конфликтов.
- Используйте \`safeUrl\` для внешних ссылок.
- Проверяйте границы возрастов и дедлайна чистыми функциями из \`core.mjs\`.
- Добавляйте \`aria-label\`, \`aria-current\` и \`aria-pressed\` для интерактивных элементов.

### Не делайте

- Не возвращайте вкладки \`Обзор\` и \`Mobile first\` в видимое сайдбар-меню.
- Не удаляйте \`renderNewOverview\` и \`renderNewMobileExact\`: тестовый контракт требует их сохранения.
- Не смешивайте старую бежевую палитру с Obsidian-токенами.
- Не используйте chevron-ступени, радиальные градиенты и декоративный noise.
- Не показывайте пустой экран без следующего действия.
- Не превращайте статус в один цветной кружок без подписи.
- Не подменяйте действие перезагрузкой страницы.
- Не добавляйте тесты, которые проверяют только наличие класса без поведения.
- Не меняйте публичные имена \`data-action\`, \`data-view\` и экспортируемых функций без обновления тестов.
- Не считайте интерес к пробному уроку оплатой.
- Не отправляйте внешние сообщения из UI без отдельного серверного действия и аудита.

## 4. Тестовые контракты и инварианты

### 4.1. Frontend-контракт

\`booking/frontend.test.mjs\` закрепляет:

- единый NEW shell;
- наличие \`renderNewView\`, \`renderNewAdminExact\`, \`renderNewConfirmation\`, \`renderNewBookingBoard\`, \`renderNewScheduleExact\`, \`renderNewUsersExact\`, \`renderNewCompensationExact\`, \`renderNewPaymentsExact\`, \`renderNewOverview\`, \`renderNewDrawerExact\`, \`renderNewReportExact\`, \`renderNewMobileExact\`;
- отсутствие \`renderUiModeSwitcher\` и \`new-sidebar-nav\`;
- наличие Control Tower, очереди, drawer и статистики по часам;
- реальные действия \`export-hour\`, \`reassign-drawer\`, \`reserve-drawer\`;
- сохранение скрытых legacy функций для контрактов;
- бизнес-дату по Москве;
- безопасные внешние ссылки;
- регистронезависимый CRM-поиск;
- корректный deadline подтверждения;
- изолированное хранение черновиков;
- дефицит по возрастной eligibility;
- одинаковую фильтрацию часа для scheduled и cancelled записей.

### 4.2. Соседние UI-контракты

\`booking/booking-wizard.test.mjs\` проверяет:

- доступные слоты;
- шаги визарда;
- сохранение черновика;
- выбор даты и времени;
- блокировку недоступного слота.

\`booking/operations-ui.test.mjs\` проверяет:

- Control Tower;
- age tags;
- часовой drilldown;
- назначения и резервы;
- отчёт и оплату.

\`booking/legacy-ui.test.mjs\` и \`booking/source-intake-ui.test.mjs\` защищают legacy-переходы и intake-экран. Новый UI не должен удалять их функции.

### 4.3. Backend и полный запуск

Локальная проверка:

~~~powershell
node --test booking/*.test.mjs
node --test tests/*.mjs
~~~

Полный проектный запуск:

~~~powershell
npm test
~~~

Критерий релиза: 66/66 целевых тестов проходят без ошибок. Если текущая ветка содержит больше тестов, полный запуск также должен завершиться с кодом 0.

### 4.4. Инварианты состояния

- \`confirmationStatus="confirmed"\` не может стать overdue.
- \`isHourOverloaded()\` учитывает дефицит возрастной группы.
- \`filterHourBookings()\` применяет час, возраст и поиск ко всем состояниям записи.
- Каждая мутация передаёт \`version\`, если сервер поддерживает optimistic concurrency.
- \`safeUrl()\` принимает только \`http:\` и \`https:\`.
- Черновик одного пользователя не читается другим пользователем.
- После отмены запись остаётся в журнале.
- После восстановления сервер повторно проверяет capacity и пересечения.
- Отчёт хранит точный пакет, включая \`1+1 (124к)\` и другие варианты.

## 5. Ролевые сценарии

### Admin

1. Открывает Control Tower.
2. Смотрит Bento KPI и исключения.
3. Нажимает строку часа с дефицитом.
4. В drawer проверяет возрастную нагрузку и список учеников.
5. Назначает МИМК или оставляет резерв.
6. Экспортирует CSV при необходимости.
7. Переходит в журнал отмен и запускает перезапись.

Критерий успеха: администратор понимает дефицит за один экран и выполняет действие без потери выбранного часа.

### KC / менеджер подтверждения

1. Открывает очередь подтверждения.
2. Сортирует записи по дедлайну.
3. Открывает CRM из строки.
4. Подтверждает запись или переносит её.
5. Видит обновлённый статус и причину ошибки.
6. Возвращается к очереди без полного reload.

Критерий успеха: просроченная запись выделена янтарём или розовым цветом и имеет явное следующее действие.

### Confirm

1. Проверяет \`2 ч\` SLA.
2. Обрабатывает pending записи.
3. Не видит confirmed запись как overdue.
4. Использует \`Обновить\` для синхронизации.
5. Проверяет резервные записи в Control Tower.

Критерий успеха: подтверждение сохраняется идемпотентно и не создаёт дубль.

### MIMK

1. Открывает \`Мой день МИМК\`.
2. Видит текущий урок в hero-блоке.
3. Начинает урок.
4. Завершает урок.
5. Заполняет отчёт с точным пакетом продаж.
6. Видит урок в истории и отсутствие незаполненного отчёта.

Критерий успеха: от назначения до отчёта проходит один последовательный поток.

## 6. Проверка качества

### Функциональная проверка

- Запустите оба пользовательских test-командных набора.
- Проверьте вход и загрузку данных.
- Переключите дату.
- Откройте Control Tower и drawer.
- Выберите возрастной чип.
- Подтвердите pending запись.
- Отмените запись и откройте журнал.
- Запустите перезапись.
- Заполните отчёт и выберите точный пакет.
- Проверьте восстановление и optimistic conflict.

### Визуальная проверка

Проверяйте минимум четыре ширины:

~~~text
1440 px — Control Tower и drawer
1280 px — очередь и расписание
768 px — планшетный переход
390 px — мобильный поток
~~~

На каждой ширине проверьте:

- нет горизонтального overflow у shell;
- активный элемент виден;
- текст не обрезается без tooltip;
- фокус виден с клавиатуры;
- contrast статусов достаточен;
- skeleton не прыгает при загрузке;
- radar-dot текущего часа не мешает чтению;
- drawer закрывается Escape.

### Anti-slop чеклист

- [ ] Нет \`#c99d65\` и \`#806d57\`.
- [ ] Нет случайных градиентов.
- [ ] Нет декоративных chevron-ступеней.
- [ ] Все карточки используют Double-Bezel.
- [ ] Цвет статуса совпадает с семантикой.
- [ ] Нет лишней вкладки \`Обзор\` в меню.
- [ ] Нет лишней вкладки \`Mobile first\` в меню.
- [ ] \`renderNewOverview\` и \`renderNewMobileExact\` сохранены.
- [ ] Текущий час имеет \`.is-current-hour\` и radar-pulse.
- [ ] Возрастные чипы интерактивны.
- [ ] Отмены имеют \`Перезаписать\`.
- [ ] Отчёт показывает точный пакет.
- [ ] Drawer содержит реальные действия.
- [ ] Основной CTA использует индиго.
- [ ] Pending использует янтарь.
- [ ] Confirmed использует изумруд.
- [ ] Cancelled и deficit используют rose.
- [ ] Числа используют tabular numerals.
- [ ] Анимации используют \`cubic-bezier(.16,1,.3,1)\`.
- [ ] Уменьшенное движение поддерживается через \`prefers-reduced-motion\`.
- [ ] Нельзя завершить работу по одному screenshot без тестов.
- [ ] Нельзя заявить 66/66 без свежего запуска команд.

## 7. Контроль изменений

Перед коммитом проверьте:

~~~powershell
git diff -- booking/styles.css booking/app.js booking/index.html
git diff --check
node --test booking/*.test.mjs
node --test tests/*.mjs
~~~

В описании изменения укажите:

1. какой пользовательский поток изменился;
2. какой контракт защищает изменение;
3. какие команды прошли;
4. какой риск остаётся непроверенным.

Плейбук считается применённым только после свежего запуска тестов и ручного smoke-check основных ролей.
